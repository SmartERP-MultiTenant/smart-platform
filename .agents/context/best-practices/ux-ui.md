# UX/UI — best practices (harvested from this codebase)

Purpose: the design system (tokens + component rules) and the RTL/Arabic + premium design standards this repo commits to.

## Key points

- **The public marketing surface is LIGHT-ONLY (P4.18 decision, 2026-09-14).** `components/site/**` + `components/layouts/PublicLayout.tsx` render light only: no theme toggle, no `dark:` variants, and **no dark palette is planned**. The toggle was removed from the retired landing header (`LandingHeader`, deleted when the site design replaced the landing) because `NEXT_PUBLIC_DARK_MODE=false` already gated it off (`.env:34`, `lib/env.ts:109`) — a visible control that did nothing; `components/site/Navbar.tsx` has no toggle either. Dark surfaces come from the `ds-gradient-dark` class (`--ds-gradient-dark`), never from a toggled theme; `--ds-ink-*` is reserved for those gradient surfaces and today has no consumer outside `pages/design-system.tsx`. The authenticated account/app shell keeps its own `useTheme` behaviour (`pages/_app.tsx:44`, `components/shared/shell/Header.tsx:166`, `components/account/UpdateAccount.tsx:19`), which the same flag also gates — do not assume removing the landing toggle removes theme support app-wide. **Token discipline does not hold on this surface:** the retired landing was fully token-backed (no raw hex outside `styles/tokens.css`), but the adopted `components/site/**` is a faithful port of the reference and carries raw hex values with **no `var(--ds-*)` references at all**. `--ds-gray-*` is the Tailwind **slate** family rather than Tailwind gray.
- **Design tokens are the single source of truth.** `styles/tokens.css` v2: indigo-royal primary scale (50–950), bronze accent (brand-distinctive), ink/dark surfaces, semantic colors, gradients (brand/dark/bronze), radius incl. pill, 3-tier layered shadows, motion tokens. **Reference `var(--ds-*)` everywhere — never hardcode hex in components.** Legacy aliases (`--ds-primary`, `--ds-accent`) are kept for v1 compat. **`--ds-text-muted` resolves to `--ds-gray-600` (`#475569`), not `--ds-gray-500`** (revalued 2026-09-17): as `#64748b` it passed on white (4.76:1) but gave only **4.34:1 on the `--ds-gray-100` surface** (`#f1f5f9`) — below the 4.5:1 AA threshold for normal text, which made it the source of eight contrast failures in the design audit. `#475569` gives **7.58:1 on white** and **6.92:1 on `--ds-gray-100`**. Muted text on any gray surface must use `--ds-text-muted`, never `--ds-gray-500` directly.
- **Fonts (next/font):** Cairo = Arabic body · Almarai = Arabic display · Tajawal = alt · Montserrat = Latin/numbers. `.font-ar` / `.font-en` utilities resolve the `--font-*` vars directly (they are page-scoped via the root class — see `best-practices/performance.md`). Arabic line-height token `--ds-leading-body: 1.85`; RTL is `dir="rtl"` with mirrored layout.
- **Premium ≠ AI-slop (from `docs/design/design-synthesis.md`):** one signature color + warm secondary (not generic purple-blue on white); dark surfaces used with intent (hero/stats/footer); real product UI as hero art; layered soft shadows not heavy drop shadows; trust signals above the fold (compliance badges, stats, client logos); pill radius **only** for CTA buttons. No emoji in place of real metrics, no stock-feel imagery.
- **Component conventions:** cards 16–20px radius, interactive elements 8–12px; buttons solid/outline/ghost/link + sizes + disabled; inputs 12px radius with 4px focus ring (`--ds-primary-100`); badges status/compliance/tag variants; alerts use semantic tokens (success/warning/danger/info). Section header pattern: icon tile + Arabic title + uppercase EN label (`Section` component in `pages/design-system.tsx`).
- **Admin shell dashboard (teams/[slug]/dashboard):** stat cards use the daisyUI `stats` component with shell gray/dark tokens (not hex palettes) · charts (ApexCharts) render **client-only** via `next/dynamic({ ssr: false })` and follow the theme through `.dark` on `<html>` (MutationObserver in `components/dashboard/charts/useIsDark.ts`) · chart series colors are the token hexes from `styles/tokens.css` (`--ds-primary-600/400`, `--ds-bronze-500`) — the only sanctioned hexes · restricted-permission sections render as hidden/empty, never as fake zeros.
- **Do/Don't rules** live in the design-system page "قواعد الاستخدام" and in `docs/design/design-synthesis.md`: gradient only in hero/CTA; bronze reserved for pricing/premium; no mixing radii inside a component; white text on dark blue; ink surfaces for hero/stats/footer; avoid heavy 3D shadows.

## Public marketing surface — five invariants (2026-10-10)

Harvested from the marquee/contrast pass over `components/site/**`. All five are arithmetic, not taste:

- **An infinite horizontal row animates on the inline axis, never physically.** The public site is Arabic-first (`pages/_document.tsx` sets `dir="rtl"`; the default locale is `ar`), and a `w-max` flex track overflows to the **left** in RTL. A physical `translateX(0 -> -50%)` walks the track's leading edge away from the clip and the row empties (in LTR the same code only breaks once the clip is wider than one copy). Use `components/site/motion/Marquee.tsx`: it renders **two identical units** of the caller's list repeated until one unit is at least as wide as the widest container, every item carries the same logical trailing gap, and it animates exactly one unit — `-50%` in LTR, `+50%` under `[dir='rtl']` (a mirrored `animation-name`, so the SSR output is already correct and no JS measurement runs). **Invariant: blank is impossible while `unit >= clip`.** The bound is per caller because the clip is not one number: the testimonial rows sit in a `max-w-[1700px]` container (unit 4140–4989px at `repeat={3}`), while **the tools icon strip's clip is uncapped** and tracks ~0.65 × viewport (884px at 1440 → 1623 at 2560 → 3313 at 5120), so it uses `repeat={5}` (unit 5100px at `md`, 4500px below) to stay blank-free to an ~7800px clip; at `repeat={3}` (3060px) it measurably blanked 8.5% of the row at 5120. Item spacing is that primitive's `gap` prop, not a `me-` class on the items: the pitch must be uniform across the unit boundary or `-50%` is not one unit.
- **Body copy on a coloured band needs an opaque, distinct card, and every gradient stop is text colour.** A card filled with a 2% tint of the band it sits on (`rgba(0,37,233,.02)` over `linear-gradient(rgba(0,37,233,.14), #ABBBF2)`) is the band's own colour; `#5A5A5A` on `#ABBBF2` is **3.65:1**. Cards on a coloured surface are opaque white with a blue-tinted border and a soft blue shadow (band palette, no new hue); `#5A5A5A` on white is **6.90:1**. A `bg-clip-text` gradient's stops **are** the text fill, so every stop must itself clear 4.5:1 — `#ABBBF2` glyphs are 1.89:1 on white and 1.34:1 on the tools band. Likewise a white label on a gradient that sweeps `background-position` passes every point of the gradient under the text, so _every_ stop must be legible (min stop in the repaired CTA: `#1234E8` at 7.83:1 on white).
- **A coloured band surface stops flush with its own content bottom.** The tools surface used `bottom-[221px] md:bottom-[167px]`, which stacked with the next band's `pt-[270px] md:pt-[254px]` into ~421–491px of continuous white. The reference's card overhang is not reproduced: the surface runs to the band's content bottom (`bottom-0`) and the following band keeps only its own top padding.
- **A gradient eyebrow is only as legible as its palest stop, so the sheen has to be a legible blue.** The reference's stop list ran backwards (`#ABBBF2 35%, #ABBBF2 0%, #ABBBF2 0%`), and the two `0%` stops clamp up to 35%, leaving a long run of `#ABBBF2` glyphs. **The rule is not one universal stop list — it is that every gradient stop that can sit under text must clear 4.5:1.** The repaired eyebrows share `#0025E9 0%, #0025E9 30%, #1234E8 55%, #0025E9 100%` — verified per stop: `#0025E9` is 8.60:1 on white, 7.96:1 on `#F3F6FE`, 6.59:1 on the tools band's top composite (`rgba(0,37,233,.14)` over white) and 4.56:1 on `#ABBBF2`; `#1234E8` is 7.83 / 7.24 / 6.00 / 4.15 for the same four surfaces — but `ToolsShowcase.PRIMARY_BTN_CLS` deliberately uses a **different six-stop list** (`#0025E9 0%, #0025E9 15%, #1234E8 45%, #1234E8 55%, #0025E9 85%, #0025E9 100%`) because that gradient is a `background`, not a `bg-clip-text` fill: its label is white, and every one of its stops is ≥7.83:1 against white, so the rule holds even though the stops differ. **`#1234E8` does not clear 4.5:1 on pure `#ABBBF2` (4.15:1)**, so a repaired eyebrow must never sit on that surface, and a pale `#ABBBF2` glyph is arithmetically impossible at 4.5:1 anywhere. When a stop list feeds a `background` CTA instead of `bg-clip-text`, the rule moves to the **label**: white must clear 4.5:1 against _every_ stop, because a sweeping `background-position` passes the whole gradient under the text.
- **A fixed glyph box must track the fluid font-size it holds.** `ServicesShowcase`'s numerals were `text-[clamp(...)]` with a fixed `leading-[68px] w-[95px]`; the clamp passes 68px at ~908px and needs ~120px of glyph at 1920, so both axes clipped. Use `w-fit` (never narrower than the content) with a `min-w-[1.35em]` floor — `em` resolves against that element's own fluid font-size, so floor and font scale together — and a unitless `leading-[1.05]` so the line box tracks the font too.

## Mobile chrome — defect-fix rules (2026-10-10)

- **A full-bleed overlay wrapper is `pointer-events-none`; only its controls opt back in.** `pages/index.tsx` wraps `Navbar` in an absolutely positioned full-width box over the hero, so its whole ~100px band was a click dead zone. Put `pointer-events-none` on the wrapper _and_ on the header, then `pointer-events-auto` on the two glass pills and the drawer wrapper — **not** on the header root, whose full-width box is the dead zone. `pointer-events` is inherited, so a child has to opt in.
- **Below 480 a 40px gutter cannot hold a lockup + trigger.** At 320 the header's `px-10` leaves ~200px inside the pill, but the lockup (36px mark + 10px gap + Montserrat ExtraBold "SMART PLATFORM" at 20px/tracking-wide = 207.1px, measured from the font's `hmtx`) is 253.1px — and because the site is RTL the overflow leaves past the _left_ edge, where the hamburger sits, hidden by `overflow-x-clip`. Shrink the gutter (40 -> 12px) and the pill's own padding (20 -> **8px**) below 480, step the wordmark down (20 -> 17px), and restore the reference 40px gutter at 480. At 12px of pill padding the measured content (lockup 222px + 10px `pe-2.5` + the 40px trigger = 272px) exactly equalled the pill's inner width, i.e. zero slack — one pixel of font-fallback drift would clip the trigger — so the padding is 8px and the slack is ~8px. Prove the trigger stays inside the viewport at 320/360/390 in both directions.
- **A drawer that claims `aria-modal="true"` must trap Tab**, and the trap must not fight the a11y tree. Keep the drawer mounted and hide it with an inline `visibility: hidden` — a Tailwind `invisible` class is invisible to jsdom's accessibility tree, so `queryByRole('dialog')` leaks — which still lets an opacity/visibility 300ms transition run; drive it with `motion-reduce:transition-none` (Tailwind's `rtl:` variant is real: `&:where([dir="rtl"], [dir="rtl"] *)`). Widen the panel at tablet (300 -> 380 -> 420px) while keeping `max-w-[85vw]`.
- **A mounted overlay's `visibility` transition is per-state, because the two directions need opposite timing.** Opening is `visibility 0s 0s`: zero duration and zero delay create no transition at all, so the property is already `visible` when the open effect's `closeRef.current?.focus()` runs in the same commit. Closing is `visibility 0s 300ms`: a transition is created with zero duration and a 300ms delay, so the computed value stays `visible` for exactly the fade-out and then flips. A single shared `transition-[opacity,visibility] duration-300` is the bug — Chromium still computes `hidden` at the moment of the focus call and **silently drops the request**, leaving focus on the hamburger _behind_ the modal, while jsdom honours the same call so the unit test stays green. Only a browser catches this class of defect. Tailwind emits the `motion-reduce:transition-none` variant after the arbitrary `[transition:…]` utility (verified in compiled CSS: line 4479 vs the `@media (prefers-reduced-motion: reduce)` block at 5143), so reduced motion stays instant.
- **A closed-but-mounted overlay must be `inert`, not just `visibility: hidden`.** The exit transition deliberately keeps the element painted for 300ms, and `visibility` only flips at the end of that window, so for the whole fade the closed drawer is still in the accessibility tree and still tabbable (3/3 trials: Tab entered the scrim, then the close button, then the nav links). `inert` closes that window the instant the state flips. On React 18 — this repo's version — pass it as the empty string: a boolean value is dropped with a console warning and renders **no attribute at all**, while `inert=""` is the HTML boolean-attribute form that actually marks the subtree inert. The `@types/react` typing declares the prop as a boolean, so the string needs a narrow cast. Set `aria-hidden` alongside it: Playwright's role selector resolves hidden state from computed style and `aria-hidden` only, never from `inert`, so an `inert`-only fix still measures as a live `dialog` in that engine.
- **Footer type must respond below 1280**, not just the layout: the `<details>` accordion title steps 20 -> 17/18px, the "Downloads:" heading 24 -> 20px, badge labels and link items step down one notch, and row 1's split moves from `min-[480px]` to `min-[640px]` because its `w-[47%]` brand column is 186px at 480 (396px content box) against a 253.1px lockup. **The split is not the whole fix:** from 640px up the tagline still sat beside the lockup in that 47% column, and 253.1px + 16px gap + the tagline's longest word outgrew the column's ~241–261px until roughly an 845px viewport, so flexbox crushed the 394-char tagline to its longest unbreakable word. A flex item's hypothetical main size is its flex basis clamped by its min, so `basis-0 grow min-w-min` on a **wrapping** row drops the tagline onto its own full-width line exactly when the longest word no longer fits, and `grow` reproduces the old `w-[68%]`-shrunk box pixel for pixel above that point.

## Rules for new UI

1. Use tokens (`var(--ds-*)`) + the `Section`/`FieldLabel` helper patterns; extend the design-system page when adding a new component.
2. Arabic-first RTL with EN parity; use `dir="rtl"` + `font-en` for Latin spans; generous line-height for Arabic.
3. Trust hierarchy for this market: compliance (ZATCA/ISO) > customer counts > named logos > testimonials.
4. If a new visual pattern is added, showcase it on `/design-system` and update Do/Don't + this file.
5. Dashboard/insight UIs: wire charts and stat cards to real data (SWR + `models/dashboard.ts`); prefer tables with view-all links over pagination on overview pages; never create side effects (e.g. Stripe customer creation) from dashboard reads.
