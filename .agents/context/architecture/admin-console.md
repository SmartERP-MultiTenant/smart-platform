# Platform-admin console (P5.2–P5.7) + audit store

Purpose: the `/admin` operator surface — its pages, its API routes, the durable audit store every mutation writes to, and the error contract all admin routes share.

## Key points

- **Guard-first, always.** Every `/api/admin/*` handler calls `requirePlatformAdmin(req, res)` as the **first statement inside its `try`**. It _throws_ `ApiError` (401 no session / 403 not `PLATFORM_ADMIN`) rather than sending, so there is exactly one response path and no double-send. The rule is now literally true of every route: `revenue` was the last hold-out (its `req.method` switch ran before the guard, so an anonymous `POST` answered **405 where the contract promises 401** — it leaked verb information before auth) and now guards in the handler too. The fresh narrow DB `select: { platformRole }` is the authority — never the JWT claim. `middleware.ts` adds a defense-in-depth gate over `/admin/**` + `/api/admin/**` (JSON 401/403 for API routes, plain-text 403 for pages). Returns the safe actor `{ id, email, name }`.
- **Surface map.** Pages: `/admin` (tenants + ERP health) · `/admin/revenue` · `/admin/users` · `/admin/rules` (P5.6 per-plan module toggles) · `/admin/audit-logs` (P5.4) · `/admin/tenants/[teamId]`; single nav in `components/admin/AdminNav.tsx`, which inherits direction from `<Html dir>` — never re-add `dir="rtl"` locally. API reads: `dashboard`, `tenants/[teamId]`, `users`, `users/[id]`, `revenue`, `audit-logs`. API mutations: `users/[id]{,/[action]}` (P5.5) · `subscriptions/[teamId]{,/extend,/cancel,/trial-override}` · `rules/plans/[planId]`, `rules/sync`.
- **No client-supplied credentials.** `teamId` is the **platform** id; routes resolve `Team.erpTenantId` server-side and pass only that to the ERP M2M client. No route accepts a client-supplied ERP key, access token or tenant id, and none reads `Team.erpAccessToken`.
- **ERP call budgets are asymmetric on purpose — do not "tidy" them together.** Every M2M **mutation** inherits its abort budget _inside_ the wrapper (`m2mMutationInit` + `ERP_MUTATION_TIMEOUT_MS`, 15s), so a new wrapper cannot forget it. The M2M **read** that builds audit snapshots (`getTenantBillingSubscription`) deliberately has **no** wrapper-side budget: the four `subscriptions/[teamId]/*` routes pass `AbortSignal.timeout(ERP_M2M_READ_TIMEOUT_MS)` (3s) **at the call site**, because `adminDashboard` pins its own read budget and two-argument callers must not start sending `signal: undefined` — a test pins that the wrapper adds no signal by default, so moving the read budget into the wrapper is a contract break, not a tidy-up. A read timeout is **best-effort**: it must never fail the operator's mutation — the route records `beforeFetchError` (or degrades the after-state) and the write proceeds on an unresponsive ERP.
- **Audit store — one row per operation.** `enum AdminAuditStatus { STARTED SUCCEEDED FAILED }` + `model AdminAuditLog` (`actorId String?` SetNull→`User`, `actorEmail`/`actorName` snapshots, `action`, `targetType`/`targetId`, `before`/`after`/`metadata` JSONB, `errorCode`, `createdAt`/`updatedAt`; indexes on `createdAt`, `[actorId, createdAt]`, `[targetType, targetId, createdAt]`; migration `20260912180000_add_admin_audit_log`). `createAdminAuditStart()` inserts `STARTED` and **returns the row id**; the caller MUST thread it into `completeAdminAudit({ logId })` / `failAdminAudit({ logId })` so the terminal event UPDATEs that same row — passing `logId: null` silently _creates_ a second row and strands the `STARTED` one. `lib/adminAudit.ts` `recordAdminAudit()` wraps the helpers, returns the affected id, and also supports standalone single-phase terminal logging. Audit **writes** never throw into the caller's mutation (a failed audit write must not roll back a real operator action), but audit **reads** do — `getAdminAuditLogs` propagates, so a broken store answers 5xx instead of rendering a healthy empty table.
- **Redaction is a choke point, not a convention.** `redactAuditPayload()` runs inside every write path, so no call site can bypass it: it is **two layers**, and knowing which one catches what matters. _Layer 1, key-based:_ the key is NFKD-normalised then stripped of non-alphanumerics (`X-Platform-ApiKey` → `xplatformapikey`, `Set-Cookie` → `setcookie`, fullwidth `Ａuthorization` → `authorization`) and matched against a credential denylist. _Layer 2, value-based:_ values are scrubbed **regardless of their key** — auth-scheme tokens (`Bearer …`), `postgresql://user:…@host` DSNs, `Sensitive-Header: value` lines, vendor prefixes (`sk_live_`, `whsec_`) and long high-entropy tokens (≥40 chars carrying upper+lower+digit — deliberately conservative, so ISO dates, UUIDs and kebab-case codes survive intact). `Map`/`Set` become `[omitted] Map`/`[omitted] Set` (they expose no own enumerable properties, so the object branch would otherwise persist a silent `{}`), while `ArrayBuffer` and every byte view (`Uint8Array`, `DataView`, …) become `[redacted]` (they would otherwise serialise as a decodeable `{"0":byte,…}` blob under an innocuous key). Dropped keys are counted into a `console.warn`, and strings/depth/array length are clamped. `sanitizeSubscriptionSnapshot()` is the whitelist alternative for ERP subscription reads (9 fields only). `erpAccessToken`, M2M keys, passwords, auth headers and raw upstream bodies must never reach an audit row. **Bound, stated honestly:** this is a denylist against _accidental_ exposure, not a proof — a confusable-script key with no NFKD decomposition (Cyrillic `а`) still passes the key matcher, and the value scrubber is only the backstop.

## Error contract

Failures are always `{ error: { message: '<safe-error-code>' } }`. `lib/errors.ts` `apiErrorStatus` reads `error.status` (else 500), and `apiErrorMessage` echoes a **4xx** `ApiError` message but collapses every 5xx / non-`ApiError` to the stable token `internal-error`, so Prisma/SDK internals never reach the body. The one sanctioned exception is **opt-in**: `new ApiError(503, 'erp-not-configured', { expose: true })` echoes its message on a 5xx. It is reserved for a **stable, non-sensitive code** describing something the operator must be able to tell apart from a genuine fault — collapsing a misconfigured M2M key into `internal-error` makes it indistinguishable from a crash. Never set `expose` on a message carrying upstream text, a secret or an internal detail; every other 5xx still collapses. `expose` is a _claim_, so it is **verified rather than trusted**: a flagged 5xx is echoed only when its message is genuinely code-shaped (kebab-case token, `isAdminErrorCode`), so an accidental — or future — `expose` on prose, a stack fragment or an upstream body still collapses to `internal-error`. Flagging therefore cannot silently switch the 5xx rule off. Reads return `{ data: … }` (`dashboard`, `tenants/[teamId]`, `users/[id]`, `revenue`); `audit-logs` → `{ data: { items, total, page, limit, hasMore } }`.

Never forward `ErpApiError.message` — it is lifted verbatim from the ERP response body. `classifyErpError(err)` in `lib/erp.ts` is the single mapper: upstream `400→400 erp-bad-request`, `404→404 erp-not-found`, `401/403→502 erp-auth-failed`, `409→409 erp-conflict`, `422→422 erp-rejected`, other upstream `→502 erp-upstream-failure`, unparseable 2xx `→502 erp-malformed-response`, abort/timeout/network (`ECONNREFUSED`, `TypeError: fetch failed`) `→503 erp-unavailable`. Upstream 401/403 deliberately become **502**: the M2M key is a platform secret, so an upstream auth failure is never the admin's session, and returning 401 would make the admin UI log a healthy operator out. Guard the check with `err instanceof ErpApiError || err.name === 'ErpApiError'` and **keep the `name` fallback**. `instanceof` is regime-dependent here (measured, not theorised): Next's SWC bundle and jest emit native `class extends Error`, so `instanceof` is `true`, but `tsconfig.json` sets `target: es5`, and a `tsc`-compiled consumer (the `ts-node` scripts, or any future target change) emits `var _this = _super.call(this, message) || this` — the object then keeps `Error.prototype`, so `instanceof` is **false** while `name` and `status` still survive. The same ES5-safe guard is `isApiError` in `lib/errors.ts`.

- **Routes emit codes, components render copy.** `adminErrorCopy(value, t, fallback)` (`lib/errors.ts`) maps a code to localized AR/EN copy so a raw token (`erp-not-configured`) never reaches the screen; an unknown code-shaped token falls back, while a human sentence a route still returns passes through untouched. The deliberate **platform-side refusals** have entries too (`subscription-not-active`, `end-date-not-in-future`, `end-date-not-after-current-end`, `internal-error`), which is the point: without them an operator cannot tell "this subscription is not cancellable" from "the ERP is down". Editing that map: entries are closures calling `t('<literal-key>')`, **not** a `code → key-name` string map, because `check-locale.js` only recognises a key written as a quoted string literal.
