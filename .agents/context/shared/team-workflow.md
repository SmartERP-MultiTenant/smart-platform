# Team workflow

Purpose: git layout, branch conventions, and deploy path across the three related repos — plus what's currently mid-flight so agents don't collide.

## Key points

- **Three independent repos** (not a monorepo) — `smart-platform` is a single-origin repo (`github.com/mhmd-ashrf-saad/smart-platform`, default branch `main`, mostly dependabot branches). `SmartAndPro.ERP.ClientApp` and `SmartAndPro.ERP.Inventory` are **forks**: `origin = github.com/SmartERP-MultiTenant/<repo>`, `upstream = github.com/abdelruhmangomaa/<repo>` — work flows via the org repo, with the personal repo as upstream reference.
- **Branch conventions (ERP repos) — there is no single production branch.** `development` is the active working branch (checked out by default) and is what the multi-tenant stack's server checkout has historically tracked; but as of 2026-09-20 the complete line for the ERP **API** is `deploy` — a strict superset of the vendor line and the platform line (merge `2cb867b3`, pushed over `3e6173d2`) — so `deploy` is the API's sync/build source; alongside it sit `main`, `Staging`, `deploy`, and `feature/*` (e.g. `feature/multi-tenant`), plus occasional one-offs (`Testing`, `PROJECT-ADD-NEW-FEAT`, `cashier-front`, ...). `deploy` is the **vendor-fed** line (`origin/deploy` advances through `abdelruhmangomaa` merges) and is what the team leader merges into for the **legacy** API. `main` is effectively **dead**: head `dce006c1`, last commit 2025-08-27, 749 commits behind `development`.
- **Production topology — two ERP API surfaces, and the platform calls only one (verified on the VPS 2026-09-20).** The platform's production target is **`server-mt.smartapro.com`** → nginx → `127.0.0.1:5030` → docker `erp-backend`, built from the clone at `/var/www/multitenant-smart-and-pro/Backend`, which at inspection time was checked out on branch `development` at the server-local HEAD `4a3148a9` — the stale state, not the target; the correct sync target is now `origin/deploy` (see the update bullet below). Its siblings: `platform.smartapro.com` → `5032` (`erp-platform`, running the GHCR image `ghcr.io/smarterp-multitenant/smart-platform:sha-53ab54b`) and `app-mt.smartapro.com` + `*.smartapro.com` → `5031` (`erp-front`). The running platform container proves the target: `ERP_API_URL=https://server-mt.smartapro.com/api`, `NEXTAUTH_URL=https://platform.smartapro.com`, `ERP_CLIENT_URL=https://app-mt.smartapro.com`. **Separately, `server-erp.smartapro.com`** → nginx → `127.0.0.1:5000` → systemd `server-erp.service` → docroot `/var/www/server-erp.smartapro.com` serves the per-tenant `vps_*` stack (server-demo5, server-zadalmodon, server-abwabalthuraya, server-alsakraljawal, ...) and carries **none** of the platform line; that docroot is a `dotnet publish` **output with no `.git`**, so no branch is readable from it.
- **The server-side clone is manual and silently lags.** Nothing on the VPS fetches `/var/www/multitenant-smart-and-pro/Backend`. On 2026-09-20 it sat on HEAD `4a3148a9` — a server-local, never-pushed "Merge branch 'deploy' … into development" — while its remote-tracking `origin/development` was stale at `e1a6f1e0` and the fork's real head was `3be7241f` ("ahead 122, behind 10"). Live effect: the built `PlatformBillingController` had only **three** actions (`GET subscriptions/by-tenant/{tenantId:guid}`, `POST …/extend`, `POST …/cancel`), so `GET /api/platform/billing/subscriptions`, `/packages` and `/system-modules` returned **404 in production** while `…/subscriptions/by-tenant/{guid}` returned **401** (route present, `X-Platform-ApiKey` required). **"Merged on `development`" is therefore not "live".**
- **Update the multi-tenant stack** — sync the **API** checkout to `origin/deploy`, **not** `origin/development`: `git -C /var/www/multitenant-smart-and-pro/Backend fetch && git -C /var/www/multitenant-smart-and-pro/Backend merge origin/deploy`. As of 2026-09-20 the fork's `deploy` carries the full platform line (merge `2cb867b3`, pushed over `3e6173d2`, zero conflicts) and keeps the vendor line as an ancestor, so it is the strict content superset; `origin/development` alone is **101 commits behind** it — it lacks the vendor line — and must not be used as this stack's sync target. The **client** is the opposite case: sync `Front/SmartAndPro.ERP.ClientApp` from the ClientApp repo's `development` (`git fetch origin && git merge origin/development`). Never use ClientApp's `deploy`: it has **zero** occurrences of `vps_mt`/`server-mt` and its `active_server` is `production` → `http://smartpro7-001-site2.atempurl.com/` (a plain-HTTP temporary URL), whereas ClientApp `development` has `vps_mt` → `https://server-mt.smartapro.com/api/`. Then `cd /var/www/multitenant-smart-and-pro && docker compose build backend front && docker compose up -d backend front`. **Migration files never travel through git in this family** — the team leader's standing rule is that migrations must not be pushed; they are applied on the server side and the fork keeps its migrations local, which is why `20260823153625_AddMultiTenancyPlatform` sits staged-but-uncommitted in Inventory's working tree. The code merge `2cb867b3` therefore carries **zero** migrations (377 migration files in it, byte-identical to `3e6173d2`), so any fresh database gets the platform tables from the startup snapshot-creation path (`IRelationalDatabaseCreator` / `Database.Migrate()` in `Program.cs`) rather than from a migration. `Backend/`, `Front/SmartAndPro.ERP.ClientApp` and the legacy docroot are **separate checkouts** — updating one does not update another. On 2026-09-20 `Front` was stale on `9f5ff615` (2026-08-30) and `Platform/smart-platform` sat on `main` at `d4738f42` (2026-08-30), unused because the platform runs from the GHCR image.
- **Deploy path (legacy ClientApp front)** — `Jenkinsfile` takes a `SERVER` parameter (currently `vps_erp`): `npm i --legacy-peer-deps` → (rewrites `environment.prod.ts` per server) → `ng build --configuration production` → `sudo rsync -a --delete dist/demo1/ /var/www/<target>/` (target `erp.smartapro.com`), chown `www-data`. Each `vps_*` tenant in `src/environments/environment.prod.ts` maps to a prod URL (e.g. `https://server-erp.smartapro.com/api/`).
- **Currently mid-flight (2026-08-24)** — the multi-tenant/platform feature is uncommitted in Inventory's working tree: staged migration `20260823153625_AddMultiTenancyPlatform` (+ Designer) plus modified `ERPContextModelSnapshot.cs` and `appsettings.Development.json`. Smart-platform context tracks the same feature direction (tenant registration, super-admin, billing). **Coordinate before pulling/rebasing these repos.**
- **Context rule for this family** — repo-scoped context lives in each repo's `.agents/context/`; product-wide facts live **here** in `smart-platform/.agents/context/shared/`; the ERP repos' `shared/` stubs link back via `../../../../smart-platform/.agents/context/shared/<file>.md` (their stubs sit in a category dir, so four levels up; assumes the three sit side-by-side as they do today).
